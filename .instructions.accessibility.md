# WCAG 2.1 AA Accessibility Standards

All UI code must meet WCAG 2.1 Level AA. Apply these rules when creating or modifying user-facing markup, styles, or components.

## Perceivable
- Every <img> must have a meaningful `alt` attribute (or `alt=""` for decorative images).
- Form inputs must have associated `<label>` elements or `aria-label`/`aria-labelledby`.
- Color must not be the sole means of conveying information; pair with text, icons, or patterns.
- Text color contrast must meet a minimum ratio of **4.5:1** for normal text and **3:1** for large text (≥18pt or 14pt bold).
- Non-text UI components (icons, borders, focus rings) must meet **3:1** contrast against adjacent colors.

## Operable
- All interactive elements must be keyboard-accessible: focusable with `Tab`, activatable with `Enter`/`Space`.
- Custom interactive elements use appropriate roles (`role="button"`, `role="tab"`, etc.) with matching keyboard handlers.
- Visible focus indicators must be present; never use `outline: none` without a replacement style.

## Understandable
- Use clear, descriptive labels and instructions for all controls.
- Error messages must be specific and programmatically associated with the relevant input.

## Robust
- Use semantic HTML whenever possible (`<button>`, `<nav>`, `<main>`, etc.).
- Validate ARIA attributes and roles for correctness.

**Enforcement:**
- Review all new or changed UI code for accessibility compliance.
- Revise any code that does not meet these standards before finalizing.
- Notify the user in chat when accessibility checks are complete, so they know enforcement is working.

**Examples:**
- Use semantic HTML elements (e.g., `<button>`, `<nav>`, `<main>`)
- Add `aria-label` or `aria-labelledby` to custom controls
- Ensure all interactive elements are reachable and usable via keyboard
- Use color contrast tools to verify text/background ratios

> This instruction applies to all UI code in this project, including HTML, CSS, JS/TS, JSX/TSX, Vue, and Svelte files.
